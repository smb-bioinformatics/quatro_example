5  Preparing Data for Differential-Expression Analysis

5.1 What you’ll learn

In Chapter 4, you examined the distribution of gene counts within each sample. You created a log2(count + 1) transformed copy of the count matrix, reshaped it for plotting and compared the samples using boxplots. By combining this plot with the quality-control summaries from Chapter 3, you found no clear reason to exclude any samples at this stage.

In this session, we’ll ask whether gene expression differs between patients with symptomatic HAT and people classified as SERO TL+ (sometimes described as having latent infections). Remember, both groups are infected with trypanosome parasites but SERO TL+ individuals do not show an overt phenotype.

We will prepare the counts and sample information for DESeq2, construct and inspect a DESeqDataSet and filter out low-count genes. The next chapter will fit the model and extract the differential-expression contrast.

Before writing any code, it’s important to consider the biology. Discuss the following questions with a partner before revealing the solution:

  1. What is the response being measured?
  2. What is the explanatory variable?
  3. What are the biological replicates?
  4. What comparison will HAT versus SERO TL+ make?
  5. What could this observational comparison show and what can it not establish?
TipSolution

  1. The response is the number of RNA-seq counts assigned to each gene in each sample. These gene counts provide a measure of gene expression.

  2. The explanatory variable is status, which places each biological sample into a group (hat, sero or ctrl).

  3. The biological replicates are the independently collected samples from different people within each group. Genes and sequencing reads are measurements taken from these samples, not additional biological replicates.

  4. It will compare gene expression in samples from the HAT group with gene expression in samples from the SERO TL+ group. For this comparison, a positive log2 fold change indicates higher estimated expression in HAT, while a negative log2 fold change indicates higher estimated expression in SERO.

  5. The analysis can identify genes whose expression is associated with HAT or SERO status in these samples. It cannot establish that status directly caused the differences in gene expression. Other biological or technical differences between the groups could also contribute to the observed pattern.

5.2 Load the input data

Load the count matrix and sample information at the start of the session so the workflow can be run after restarting R.

count_data <- as.matrix(read.csv(
  "m_sample_counts.csv", header = TRUE, row.names = 1, check.names = FALSE
))
sample_info <- read.csv(
  "m_sample_info.csv", header = TRUE, row.names = 1, check.names = FALSE
)

For this session we will be using the DESeq2 R package so we need to load it using the library() function. You can add this to the top of your script with the other package imports, or place it before the next code block.

library(DESeq2)

5.3 Representing the biological groups as a factor

In the HAT dataset, the status column contains the category labels ctrl, sero and hat. R can store these labels as ordinary text, but the statistical model needs to recognise that they represent distinct biological groups. We therefore have to convert status into a factor.

A factor is how R stores a variable made up of a fixed set of categories, such as biological groups. Unlike ordinary text, a factor tells R which categories exist so they can be used correctly in summaries, plots and statistical models.

sample_info$status <- factor(
  sample_info$status
)

levels(
  sample_info$status
)
[1] "ctrl" "hat"  "sero"
NoteFactor level order

The order of factor levels can affect how model coefficients are labelled. In this chapter, the direction of the biological comparison will be specified explicitly using a contrast, so we do not need to change the reference level to get the comparison we want.

5.4 Checking biological replication

Before constructing the model, we should understand how many biological samples are available for each status. The number of samples matters because DESeq2 uses the differences among samples within the same group to estimate biological variability.

Here, each column in the count matrix represents one biological sample. The genes and sequencing reads are measurements taken from those samples. They are not additional biological replicates.

As in Chapter 2, we can use the table() function to summarise the status column in sample_info to show the number of samples in each group.

table(sample_info$status)
TipTry it yourself: Interpret group replication
  1. How many biological samples are in each group?
  2. Are the groups balanced?
  3. What is the replicate in this experiment: each gene, each read, or each person/sample?
  4. Why do 30,000 genes not compensate for having relatively few samples?
  5. Which group has the least information for estimating within-group variability?
TipSolution

  1. There are 6 CTRL samples, 9 HAT samples and 6 SERO TL+ samples.

  2. The groups are not completely balanced, because they do not all contain the same number of samples. HAT has three more samples than either CTRL or SERO TL+. This difference does not prevent DESeq2 from performing the analysis.

  3. The biological replicates are the independently collected people or samples within each group. Each column of the count matrix represents one biological replicate. Genes and sequencing reads are measurements taken from those samples, not additional biological replicates.

  4. The approximately 30,000 genes are measured repeatedly in the same set of biological samples. They provide information about many different genes, but they do not provide 30,000 independent observations of the difference between HAT and SERO TL+. Additional biological samples would provide more information about how much expression varies among people within each group.

  5. CTRL and SERO TL+ have the fewest biological samples, with six each. For our planned HAT-versus-SERO TL+ comparison, SERO TL+ therefore provides less information about within-group variability than HAT. This may make estimates involving SERO TL+ less precise than they would be if more SERO TL+ samples were available.

5.5 Constructing the DESeqDataSet

DESeq2 stores the information needed for differential expression analysis in an object called a DESeqDataSet. Keeping the information together helps ensure that the counts for each sample remain connected to the correct sample information and experimental design.

A DESeqDataSet contains three connected components:

  • countData the RNA-seq counts as a matrix (genes in rows and samples in columns)
  • colData information describing the samples (samples in rows and variables in columns)
  • design = the sample variable or variables included in the model

The design formula tells DESeq2 which sample variable should be included when explaining systematic differences in the counts.

For this analysis, the design formula is:

~ status

The tilde (~) introduces a model formula. Here, ~ status tells DESeq2 that the model should include differences associated with the levels of status.

This design includes all three status groups. It does not yet specify which two groups we want to compare. We will request the HAT-versus-SERO TL+ comparison later using results().

5.5.1 Complete the function call

We can construct the DESeqDataSet object we need using the DESeqDataSetFromMatrix() helper function from DESeq2.

dds <- DESeqDataSetFromMatrix(

WarningMake sure to use the original counts

DESeq2 uses the original integer counts. The log2(count + 1) values created in Chapter 4 were used only for visualisation and must not be supplied to the model.

Make sure you are using countData = count_data and not the transformed log_count_data.

Creating a dds object organises the counts, sample information and design into one object to make sure it is in a format ready for DESeq2 to use. It has not yet fitted a statistical model or changed the original count values.

5.7 Apply a simple low-count filter

Before fitting the model, we will apply a simple pre-filter to speed up the analysis. Genes with fewer than 10 counts in total across all samples provide little information for this comparison, and removing them reduces the size of the dataset. The code uses logical operators and row selection similar to those used to identify zero-count genes in sample h1.1.

NoteYou do not need to memorise this code

For now, focus on what the code does:

  • calculates the total count for each gene in the dataset
  • identifies genes with a total count of at least 10
  • retains those gene rows.

An optional activity later in this session unpacks each operation in more detail.

# Calculate the total count for each gene across all samples
gene_total <- rowSums(counts(dds))

# Identify genes with at least 10 counts in total
keep_gene <- gene_total >= 10

# Retain the selected gene rows and all sample columns
dds_filtered <- dds[keep_gene, ]

The expression used to filter dds follows the familiar indexing pattern:

object[rows, columns]

In this case:

  • keep_gene appears before the comma, so it selects gene rows
  • nothing appears after the comma, so all sample columns are retained
TipTry it yourself: Check the result

It is always good practice to check that a statement did what you expected. Run the following code:

dim(dds)
[1] 65217    21
dim(dds_filtered)
[1] 30076    21

Compare the two outputs and answer:

  1. Did the number of genes change?
  2. Did the number of samples change?
  3. Why did filtering affect the rows but not the columns?
TipSolution

  1. The number of genes decreased because genes with fewer than 10 total counts were removed.

  2. The number of samples did not change because the filter was applied to the rows.

  3. keep_gene appears before the comma, so it selects gene rows. Nothing appears after the comma, so all sample columns are retained.

dds_filtered <- dds[keep_gene, ]

For this dataset, the dimensions should change from:

65,217 genes × 21 samples

to:

30,076 genes × 21 samples

Therefore, the filter removes:

nrow(dds) - nrow(dds_filtered)
[1] 35141

This should return 35141.

WarningWhat filtering does and does not mean

This is a simple pre-filter based only on the total number of counts available for each gene.

  • Passing the filter does not mean that a gene is differentially expressed.
  • Passing the filter does not mean that a gene is strongly expressed in every sample.
  • Failing the filter does not mean that a gene has no biological importance.
  • Filtering does not transform or normalise the retained counts.
  • Filtering removes complete gene rows but retains all biological samples.

The threshold of 10 is a simple threshold we are using to speed up analysis rather than a universal rule for every RNA-seq analysis.

We will use the new dds_filtered object when fitting the model in the next chapter.

5.8 Save the prepared data

The next chapter will reload the filtered DESeqDataSet from this file, so it is available after restarting R.

saveRDS(
  object = dds_filtered,
  file = "objects/dds_filtered.rds"
)

The count data, sample information and design have now been organised, checked and filtered. saveRDS() stores an exact copy of an R object in a file that we can reload with readRDS(), saving time in later chapters by not repeating the preparation steps.

5.10.2 Further challenge: Compare thresholds

Create a vector containing several possible thresholds:

thresholds <- c(0, 1, 10, 20, 50, 100)

Calculate how many genes would be retained at each threshold:

genes_retained <- sapply(
  thresholds,
  function(threshold) {
    sum(gene_total >= threshold)
  }
)

Combine the results into a data frame:

threshold_summary <- data.frame(
  threshold = thresholds,
  genes_retained = genes_retained
)

Calculate the number removed at each threshold:

threshold_summary$genes_removed <-
  nrow(dds) - threshold_summary$genes_retained

Inspect the result:

threshold_summary
  threshold genes_retained genes_removed
1         0          65217             0
2         1          41309         23908
3        10          30076         35141
4        20          27310         37907
5        50          23747         41470
6       100          21350         43867

Increasing the threshold should retain fewer genes. However, a more stringent threshold is not automatically better because it may discard genes containing potentially useful information.

The threshold should be chosen for a defensible analytical reason. It should not be selected by repeatedly trying different values and retaining whichever threshold produces the largest number of significant genes.
