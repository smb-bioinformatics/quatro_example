6.2 Fitting the DESeq2 model

We have now prepared a DESeqDataSet called dds_filtered containing:

  • the original RNA-seq counts
  • information describing each sample
  • the design formula ~ status
  • only genes that passed our low-count filter

The next step is to fit the DESeq2 model:

dds_fitted <- DESeq(dds_filtered)

During this step the DESeq() function performs the main calculations needed to compare gene expression between the biological groups by fitting the model. Although this requires only one line of R code, several steps take place.

Adjust for size differences between sequencing libraries

The total number of reads collected can differ between samples. A sample with a larger sequencing library may therefore have higher counts for many genes, even when there is no biological difference in expression.

DESeq2 estimates a size factor for each sample. These size factors allow the model to account for differences in sequencing depth and library composition when comparing samples.

This does not mean that DESeq2 replaces the original counts with log-transformed values. The model still uses the original integer counts.

Estimate variability among biological samples

Counts for the same gene will not be identical in every person, even when the people belong to the same biological group.

DESeq2 estimates the dispersion of each gene. Dispersion describes how much the counts for that gene vary among biological samples, beyond the variation expected from counting alone.

This is important because an apparent difference between groups is more convincing when the samples within each group show reasonably consistent patterns.

For example, imagine that two genes have the same estimated difference between HAT and SERO TL+:

  • the first gene has similar counts among the people within each group
  • the second gene has very different counts among people within the same group

The difference between groups would usually be more convincing for the first gene because there is less variability among its biological replicates.

Estimate differences associated with status

Finally, DESeq2 uses the design formula:

~ status

to fit a separate model for each gene.

The model estimates how the expected count for a gene differs among the levels of status, while accounting for library size and variability among biological samples. These estimated group differences are stored as model coefficients.

At this stage, the model contains information about all three status groups. We have not yet requested the particular HAT-versus-SERO TL+ comparison. We will do that in the next step using results().

NoteA simplified overview

For each gene, DESeq2 broadly asks:

  1. How should differences in sequencing depth between samples be accounted for?
  2. How much do the counts vary among biological samples?
  3. How large is the estimated difference between the biological groups?
  4. Is that difference large relative to its uncertainty?

The final question is assessed using a statistical test. You are not expected to reproduce these calculations yourself.

6.3 Extracting the HAT-versus-SERO TL+ contrast

Finally, we will extract our comparison of interest (HAT vs SERO TL+) using a contrast. This tells DESeq2 exactly which two groups to compare and in which direction.

res_hat_vs_sero <- results(
  dds_fitted,
  contrast = c("status", "hat", "sero"),
  alpha = 0.05
)

The three values in contrast = c("status", "hat", "sero") specify:

  1. the metadata variable being compared (status)
  2. the numerator group (hat)
  3. the denominator, or reference, group for this comparison (sero)

6.3.1 Interpreting log2 fold change

DESeq2 reports differences between groups as a log2FoldChange. This is the estimated fold change expressed on a log2 scale.

Using a log2 scale makes increases and decreases easier to compare (similar to how we transformed the counts to make them easier to compare in Chapter 4:

  • log2FoldChange = 0 means no estimated difference
  • log2FoldChange = 1 means approximately 2-fold higher expression
  • log2FoldChange = 2 means approximately 4-fold higher expression
  • log2FoldChange = -1 means approximately 2-fold lower expression
  • log2FoldChange = -2 means approximately 4-fold lower expression

The direction always depends on the order of the comparison. For HAT versus SERO TL+:

  • a positive value indicates higher estimated expression in HAT
  • a negative value indicates higher estimated expression in SERO TL+
TipTry it yourself: Practice interpreting log2 fold change

For a HAT versus SERO TL+ comparison, what would each result mean?

  1. log2FoldChange = 0
  2. log2FoldChange = 1
  3. log2FoldChange = -1
  4. log2FoldChange = 2
TipSuggested answers
  1. log2FoldChange = 0 means that there is no estimated difference in expression between HAT and SERO TL+.
  2. log2FoldChange = 1 means that estimated expression is approximately 2-fold higher in HAT than in SERO (\(2^1 = 2\)-fold).
  3. log2FoldChange = -1 means that estimated expression is approximately half as high in HAT as in SERO TL+, because (2^{-1} = 0.5). Equivalently, estimated expression is approximately 2-fold higher in SERO TL+ than in HAT.
  4. log2FoldChange = 2 means that estimated expression is approximately 4-fold higher in HAT than in SERO TL+ (\(2^2 = 4\)-fold).
WarningFold change is relative

A log2 fold change describes gene expression in one group relative to another group. It does not tell us the absolute expression of the gene.

For the HAT versus SERO TL+ comparison:

  • a positive value means estimated expression is higher in HAT
  • a negative value means estimated expression is higher in SERO TL+
  • a value of zero means there is no estimated difference between the groups

For example, log2FoldChange = -1 means that estimated expression in HAT is approximately half that in SERO TL+:

\[ 2^{-1} = 0.5 \]

The interpretation always depends on the order of the comparison.

NoteWhat each column means
  • baseMean: the average normalised count for a gene across all samples
  • log2FoldChange: the estimated effect size and direction for the contrast
  • lfcSE: the standard error of the fold-change estimate
  • stat: the test statistic used to calculate the p-value
  • pvalue: the unadjusted p-value value from the statistical test
  • padj: the p-value adjusted for multiple testing, because we have tested thousands of genes at once

In this session, we will focus mainly on log2FoldChange and padj. The log2 fold change describes the estimated size and direction of the difference, while padj describes the statistical evidence after accounting for the large number of genes tested. Neither value alone establishes biological importance.

WarningInterpreting padj = NA

Some genes have padj = NA because an adjusted p-value was not available. This can occur when a gene contains too little information for reliable testing or when it is excluded from multiple-testing adjustment by DESeq2’s internal procedures.

An NA does not mean that the gene is significantly or non-significantly different. It means that an adjusted result is unavailable.

TipTry it yourself: Interpret the summary output

Use summary(res_hat_vs_sero) to see how many genes had a padj below 0.05. Why might this number differ from simply counting genes with a raw pvalue below 0.05?

TipPossible answer

The raw p-values do not account for the thousands of genes tested simultaneously. padj applies a multiple-testing correction, so fewer genes will usually have padj < 0.05 than have pvalue < 0.05.

6.6 Saving the fitted object

Fitting the model is the most time-consuming step in this analysis, so it is worth saving dds_fitted. Later chapters will reload this object for exploratory analyses without rerunning DESeq().

saveRDS(
  object = dds_fitted,
  file = "objects/dds_fitted.rds"
)
NoteWhy save the fitted object?

saveRDS() stores an exact copy of an R object in a file. readRDS() can later reload that object, which means dds_fitted can be reused in another script or session without rerunning DESeq(). This is especially useful for larger data sets, where model fitting can take much longer.
