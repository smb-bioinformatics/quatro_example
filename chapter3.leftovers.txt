
# Step 4: Filter genes with very low counts

## Why filter genes?

The imported count matrix contains many genes with zero or very few counts across the complete experiment. These genes provide little information for estimating differences between biological groups.

For this introductory analysis, we will retain genes with at least 10 counts in total across all samples. This is a simple, documented rule for this data set. It is not a universal threshold for every RNA-seq experiment, and other strategies may also consider how many samples contain counts for each gene.

We will construct the filter in three visible stages:

1. calculate one total for each gene
2. test each total against the threshold
3. use the resulting logical vector to select rows

## Connect `colSums()` and `rowSums()`

In Chapter 2, we used `colSums()` because each **column** represented a sample:

```r
total_counts <- colSums(count_data)
```

This produced one result per sample.

Genes are stored in **rows**, so we now use `rowSums()` to calculate one result per gene:

```{r}
gene_total_counts <- rowSums(counts(dds))
head(gene_total_counts)
```

::: {.callout-tip title="Check your understanding"}
Complete these statements:

- `colSums(count_data)` works down each sample ______ and returns one result per ______.
- `rowSums(counts(dds))` works across each gene ______ and returns one result per ______.
:::

## Create the filtering decision

Test whether each gene has at least 10 total counts:

```{r}
keep_gene <- gene_total_counts >= 10
head(keep_gene)
```

`keep_gene` is a logical vector with one value per gene:

- `TRUE` means that the gene meets the threshold
- `FALSE` means that the gene does not meet the threshold

Count the decisions:

```{r}
sum(keep_gene)
sum(!keep_gene)
```

When logical values are used in `sum()`, R treats `TRUE` as 1 and `FALSE` as 0. The `!` operator reverses the values, so `sum(!keep_gene)` counts the genes marked for removal.

## Apply the filtering decision

Use `keep_gene` to select the required gene rows. We will create a new object so that the before-and-after states remain visible:

```{r}
dds_filtered <- dds[keep_gene, ]
```

Recall the indexing structure from Chapter 2:

```r
object[rows, columns]
```

Here:

- `keep_gene` selects rows marked `TRUE`
- the empty space after the comma retains all sample columns

Compare the dimensions:

```{r}
dim(dds)
dim(dds_filtered)
```

The filtered object should contain fewer gene rows but the same number of sample columns.

::: {.callout-note title="Filtering is an analytical decision"}
Filtering does not identify statistically significant genes. It defines which genes contain enough count information to be included in the planned analysis.

The rule and its consequences should be recorded because different thresholds or strategies may retain different sets of genes.
:::

# Step 5: Save the analysis-ready object

The `dds_filtered` object now contains:

- the original integer counts for the retained genes
- the information describing every sample
- the design `~ status`
- the same sample order that was checked before construction

Save the object so that it can be reused in the next chapter:

```{r}
saveRDS(
  dds_filtered,
  file = file.path(
    "results",
    "objects",
    "dds_filtered.rds"
  )
)
```

`saveRDS()` saves one R object to a file. It preserves the specialised `DESeqDataSet` structure, unlike a CSV file, which is limited to a simple table.

You can check that the file exists:

```{r}
file.exists(
  file.path(
    "results",
    "objects",
    "dds_filtered.rds"
  )
)
```

The result should be `TRUE`.

::: {.callout-tip collapse="true" title="How the object can be restored later"}
After restarting R, the saved object can be restored with:

```r
dds_filtered <- readRDS(
  file.path(
    "results",
    "objects",
    "dds_filtered.rds"
  )
)
```

Your full analysis should still remain recorded in the script. The saved object is a convenient intermediate output, not a replacement for reproducible code.
:::
