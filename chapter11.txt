# Functional Enrichment Analysis

## What you'll learn

In this tutorial, you'll use Gene Ontology enrichment analysis to identify biological pathways and processes associated with your differential expression results.

::: {.callout-note}
## Learning outcomes
By the end of this chapter you should be able to:

- map Ensembl identifiers to Entrez identifiers and quantify how much mapping loss occurs
- define an appropriate tested-gene background ("universe") for enrichment analysis
- run over-representation analysis (ORA) separately for a stated direction of change
- interpret enriched terms as hypotheses to investigate, not validated mechanisms

## Mapping Ensembl IDs to Entrez IDs

Gene ontology annotation databases index genes by **Entrez** ID, not Ensembl ID, so we need to convert.

```{r}
tested_genes <- res_hat_vs_sero_table[!is.na(res_hat_vs_sero_table$padj), ]
tested_genes$ensembl_lookup <- sub("\\..*$", "", tested_genes$gene_id)

tested_genes$entrez_id <- unname(AnnotationDbi::mapIds(
  org.Hs.eg.db::org.Hs.eg.db,
  keys = tested_genes$ensembl_lookup,
  keytype = "ENSEMBL",
  column = "ENTREZID",
  multiVals = "first"
))

mapped_genes <- tested_genes[!is.na(tested_genes$entrez_id), ]
```

::: {.callout-tip title="Try it yourself: quantify the mapping loss"}
Calculate the percentage of `tested_genes` that successfully mapped to an Entrez ID. Which classes of genes (think about gene biotypes) might map poorly, and how could that mapping loss bias your interpretation of the enrichment results?

::: {.callout-tip title="Solution" collapse="true"}
```{r}
100 * nrow(mapped_genes) / nrow(tested_genes)
```
Non-coding RNAs, pseudogenes, and very recently annotated genes often lack an Entrez entry, so they tend to map poorly. If those gene classes are enriched in one direction of your contrast, mapping loss could make that biology invisible to the enrichment analysis — this is a limitation worth stating explicitly, not a bug to silently ignore.
:::
:::

## Defining the background universe

```{r}
ora_universe <- unique(mapped_genes$entrez_id)
```

::: {.callout-important}
## Check your understanding
Why is `ora_universe` restricted to genes that were actually tested by DESeq2, rather than every gene in `org.Hs.eg.db`?

::: {.callout-tip title="Solution" collapse="true"}
Over-representation analysis asks: "are my significant genes enriched for this GO term, relative to what I could plausibly have found?" If the background included every annotated human gene — most of which were filtered out in Chapter 3 because they weren't expressed in this tissue at all — the comparison would be unfair, and could make almost any term look artificially enriched simply because expressed genes are not a random sample of the genome.
:::
:::

## Running the enrichment analysis

Let's test genes significantly higher in HAT (i.e. `log2FoldChange > 1` in our HAT-vs-SERO contrast).

```{r}
hat_genes <- mapped_genes[mapped_genes$padj < 0.05 & mapped_genes$log2FoldChange > 1, ]
nrow(hat_genes)
```

```{r}
hat_ora <- clusterProfiler::enrichGO(
  gene = unique(hat_genes$entrez_id),
  universe = ora_universe,
  OrgDb = org.Hs.eg.db::org.Hs.eg.db,
  keyType = "ENTREZID",
  ont = "BP",
  pAdjustMethod = "BH",
  pvalueCutoff = 0.05,
  qvalueCutoff = 0.20,
  minGSSize = 10,
  maxGSSize = 500,
  readable = TRUE
)
nrow(hat_ora)

write.csv(
  as.data.frame(hat_ora),
  file.path("results", "tables", "T11_ORA_higher_in_HAT_TL.csv"),
  row.names = FALSE
)
```

```{r}
hat_dotplot <- enrichplot::dotplot(hat_ora, showCategory = 15, label_format = 30) +
```
